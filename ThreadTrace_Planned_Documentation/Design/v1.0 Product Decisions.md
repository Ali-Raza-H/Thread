# ThreadTrace v1.0 Product Decisions

> [!abstract] Authority
> This document records the accepted v1.0 product decisions supplied by the maintainer. It takes precedence over earlier catalogue wording when they differ. Existing alpha behaviour is an implementation baseline to audit, not proof that every v1.0 capability is complete.

## Product boundary

- ThreadTrace serves anyone investigating an unfamiliar Python program: students, developers, security researchers, and QA engineers. Its primary purpose is to explain structure and behaviour before learning from, debugging, or modifying code.
- **ThreadTrace** is the current public product name. Branding remains editable: a later approved rename must update user-facing documentation, package metadata, configuration/data migration guidance, and related identifiers while retaining compatibility where practical. The current CLI command remains `threadtrace`.
- v1.0 is Python-only, local terminal/desktop software. Remote attachment and source-free/bytecode-only applications are out of scope. Local Host/Listener sessions across terminals are allowed.
- Users are responsible for authority to access and execute targets. ThreadTrace is intended especially for locally available and open-source source trees; an open-source licence is not blanket authorisation for every use.
- The project is open source under **GPL-3.0-only**. This supersedes the alpha's MIT metadata and requires a separate repository licence/metadata change.
- Core analysis works offline. AI is optional; cloud providers require explicit selected-context approval.

## Installation, registration, and configuration

- Development installation is `pip install -e .` in a compatible Python environment. The command is `threadtrace`.
- Use configurable per-user application directories, normally `~/.config/Thread/` on Linux, with platform-appropriate equivalents elsewhere. A YAML `config.yaml` holds nonsecret configuration and has a documented schema. Do not store secrets in ordinary YAML.
- A registered source tree may have multiple named launch profiles/interpreters. Explicit `-- COMMAND` execution runs exactly the supplied command; when it resolves `python` through `PATH`, record the resolved interpreter and arguments.
- Recognise `pyproject.toml`, `requirements*.txt`, `setup.py`, `setup.cfg`, `Pipfile`, `Pipfile.lock`, `poetry.lock`, `uv.lock`, and Conda environment files. Preserve unrecognised metadata as unclassified files.
- Exclude VCS data, ordinary environments, caches, and build artefacts by default. Include tests as a separate category. Support include/exclude globs and explicit paths.
- Follow explicitly linked external files, but never recursively traverse an external directory merely because it is symlinked. Detect loops and display both original and resolved paths.
- Rescans are manual. Source-content changes stale affected results; detectable dependency, config, and interpreter changes flag analyses that may be affected. Concurrent read-only access is allowed; scans/writes require database coordination.

## Compatibility and source model

- Linux is the primary v1.0 platform. Compatible Linux environments, including WSL as a Linux runtime, are included. macOS and Windows are best-effort until tested.
- CPython is the primary dynamic/hybrid runtime. The supported CPython versions are exactly those verified by the tracing test suite. Other implementations may receive parseable-source static analysis, but runtime support is Unsupported unless tested and explicitly enabled.
- Use built-in `ast` as the analysis baseline. Additional parsers, such as LibCST, may be introduced only when they improve compatibility, source preservation, or resolution while feeding one coherent internal model.
- Parse all syntax versions supported by configured parsers. Preserve partial scans and report per-file failures; attempt recovery only where feasible.
- Analyse ordinary and namespace packages, safe zip-source archives, generated Python text, and notebook Python cells when source text is available. Native extensions are opaque boundaries. REPL/source-free contexts are Partial or Unsupported unless explicitly instrumented.
- Show Full, Partial, or Unsupported capability at feature, project/interpreter, and relevant entity levels.

## Static-analysis requirements

- Resolve local, relative, editable, installed, standard-library, and namespace-package imports where evidence permits. Dynamic imports remain labelled, not guessed.
- Expand available third-party source only along referenced/reached symbols and necessary transitive calls; never scan unrelated dependency trees by default.
- Represent every `.py` file as a module, plus packages/namespace packages. Categorise tests separately and unreferenced code as orphan or possible entry-point, never definitively dead.
- Provide verified analysers for `argparse`, Click, Typer, `optparse`, and common command registries; Flask, Django, FastAPI/Starlette, and aiohttp; raw DB-API/SQLite, SQLAlchemy, and Django ORM. Unknown frameworks retain generic Python analysis.
- For supported APIs, identify routes, middleware, authentication/authorisation checks, validation, rate limiting, recognised SQL/queries, and relevant data relationships. WebSockets and complex protocols are later work.
- Model reflection, `eval`, `exec`, monkey patching, and dynamic imports separately. Show predicted dynamic paths only when supported by evidence; otherwise state `unknown`.
- Preserve original symbols, aliases, forwarding/re-exports, `__all__`, wildcard-import uncertainty, functions, classes, variables, and other exported names.
- Use deterministic structural complexity heuristics for straight-line operations, loops, nested loops, recursion, and selected standard operations. State bounds, assumptions, called-function costs, and worst-case assumptions; otherwise report unknown/unsupported. AI does not make Big O claims.
- Sensitive-data taint analysis is out of scope. This does not waive secret redaction for exports and cloud AI.
- Detect resolvable literal/configuration/f-string/template/package-resource paths and mark dynamic paths as unresolved.

## Evidence and confidence

The primary evidence labels are **observed at runtime**, **statically resolved**, **heuristically predicted**, and **unknown**. An optional numeric score is permitted only with a documented, calibrated computation. The alpha's `confirmed/high/possible/unknown` labels must be mapped or migrated without obscuring provenance.

Potentially unreachable code means no path from analysed entry points exists in the current model; dynamic, indirect, and external invocation remain possible.

## Dynamic execution and tracing

- Run targets in a child process only. Support explicit scripts, modules, package entries, tests, and arbitrary commands. Default target `cwd` is the project root; `--cwd` overrides it.
- Instrumentation may combine `sys.settrace`, `sys.monitoring` where available, audit hooks, `sys.setprofile`, library adapters, and appropriate AST/bytecode transformation. Select a compatible mechanism per interpreter/event requirement and expose unsupported events.
- Add documented instrumentation environment variables, including `PYTHONPATH` where required, while retaining normal target environment inheritance and recording collisions/overrides.
- On timeout, offer pause/inspect, continued execution with a new timeout, or termination. User stop sends graceful interruption first, with an explicit emergency termination path and process-group cleanup where feasible.
- Trace project code by default; selected reached third-party code can be expanded. Support separate recording and presentation filters, always distinguishing hidden information from unrecorded information.
- Required capability categories include calls, lines, returns, exceptions, yields/resumes, imports, C calls, audit, and concurrency-related events where underlying instrumentation supports them.
- Use safe, cycle-aware, identity-preserving value representations with configurable budgets. Capture variable changes by default and distinguish rebinding from observed in-place mutation. Assign object IDs per run; treat C-extension state as partial.
- Normal breakpoint/tracepoint conditions use a restricted read-only grammar: arithmetic, comparisons, Boolean logic, membership, and safe attribute reads. Unsafe full Python evaluation belongs only to explicit experiment mode.
- Breakpoints are session-only and address file/line with optional symbol identity. Invalidate/revalidate them when source changes. Record raise, propagation, handling, re-raise, suppression, and termination where observable, including control-flow exceptions.
- Record wall-clock, monotonic elapsed, and CPU time where available. Runtime history is an event viewer with reconstructed captured state; replay checkpoints are not initial scope.
- Capture failure reports with traceback, exception details, source hash/location, call chain, captured state, relevant side effects, timestamps, and related functions.
- Support native trace-derived coverage and compatible `coverage.py` import, labelling granularity differences.

## Concurrency, processes, and local Host/Listener

- Support threads, `asyncio`, `multiprocessing`, and instrumentable Python child processes initially. Preserve per-run thread/task IDs with run IDs; cross-run identity is unnecessary.
- Attempt supported Python-child instrumentation inheritance. Record PID, PPID, executable/argv, lifecycle, and whether children are instrumentable Python, uninstrumented Python, or non-Python.
- Observe standard locks, conditions, semaphores, joins, async waits, and queue/task waits where possible. Deadlock/race findings are heuristic unless a well-defined observable pattern permits a deterministic detector.
- Existing-process live attachment is deferred. Discovery may register/scan a visible project, but is not tracing.
- **Host** starts a target under tracing while preserving its terminal/TUI. **Listener** connects to one active local host session, displays trace state, and may expose the same explicitly permitted dynamic controls while keeping the target terminal separate.
- Host/Listener uses a current-user local IPC socket: Unix-domain sockets where supported and a suitable loopback-only alternative on Windows. No remote connections, public binding, user-login service, or encryption requirement exists for permissioned local sockets. Validate session identity and restrict access to the current user. One active listener is permitted per host session.

## Runtime resource observation

- Use verified adapters for `requests`, `httpx`, `aiohttp`, and available `urllib`/`urllib3` paths. Capture network metadata by default; payload capture is a configured tracing level, bounded and stream-safe. Never consume streams or otherwise change target semantics merely to capture them.
- Redact known credentials, cookies, authorisation headers, passwords, tokens, API keys, and private keys for exports/cloud AI. Local unredacted viewing/export requires an explicit warning. Limits are configurable and truncation is visible.
- Initial protocol visibility includes Python-level HTTP boundaries, FTP and generic TCP where hooks allow it. TLS interception and packet-level decryption are deferred.
- Support `sqlite3` and verified DB-API/SQLAlchemy/Django ORM adapters. Query parameters are locally captured when DB tracing is enabled; rows are opt-in/limited previews and must not consume cursors. Track transactions, commits, and rollbacks; nested transaction/savepoint semantics are Partial initially.
- Trace supported filesystem open/read/write/create/rename/delete/stat/permission/import/resource operations. Content capture is explicitly configured, bounded, and must preserve target read behaviour.
- Run a best-effort pre-run scan for obvious side effects and report observed effects at runtime. It is not a safety guarantee.

## Hybrid experiments

- Experiments run in a temporary project-copy workspace. They never overwrite original source; patches persist in named experiment workspaces during a session and can be explicitly exported.
- Real network, filesystem, database, and subprocess effects may escape that copy. High-impact/untrusted execution requires clear consent; use an OS sandbox when available for actual containment.
- **Ignore/filter** only hides trace presentation or collection. **Disable** changes execution with an explicit return, raise, or mock policy.
- Resolve aliases and supported bound imports when patching; warn where pre-bound references cannot change. Patches apply to fresh runs, not already-active frames.
- Support full Python function/class definitions and temporary workspace-file edits first. Imports/helpers may be added. Support ordinary functions, classes, instance/static/class methods where effective; decorators, closures, descriptors, generators, coroutines, and native functions must expose capability status rather than silently failing.
- Validate syntax and show diffs, diagnostics, tracebacks, and related frames. Preserve workspace diffs/history after a crash; do not promise restoration of heap or external state.
- Where feasible, permit experiment-mode editing of locals/globals/attributes/collections. Closure cells and optimised locals may remain Partial. Inputs may be literals, JSON, observed-object references, and explicit advanced Python expressions/constructors.
- Named persistent instances can survive method calls inside an isolated experiment session. Dependency supply combines reliable discovery, fixtures, mocks, injection, and optional harness code.
- Side effects include mutations, globals, filesystems, networks, databases, processes, and I/O. Override precedence is: explicit per-call/per-experiment override; named patch; adapter mock/replay; original behaviour. Same-level conflicts are errors.
- Replay supported adapter data for HTTP, database, filesystem, time/random, and other verified adapters. Control seed, time, UUIDs, environment, and supported scheduling; do not promise portable PID control or runtime checkpoints.
- Automated input generation is later/experimental. Begin with boundary presets and user generators; Hypothesis is optional and general fuzzing later. Preserve inputs that reveal paths, exceptions, crashes, timeouts, divergent output, or meaningful side effects.
- Compare returns, exceptions, calls, state/object changes, side effects, and timing with structural equality where valid, semantic/identity comparators where needed, floating-point tolerance, and `unknown` for incomparable/nondeterministic values.

## Persistence, export, and investigations

- SQLite stores indexed project metadata, scans, diagnostics, reports, and references. Use a configurable per-user default with an explicit per-project storage option; never silently create project-local metadata.
- Version application, database schema, trace, and export formats independently. Migrate transactionally, back up before destructive conversion, and reject unknown newer formats clearly.
- Exports are portable with version/source metadata. Required user-facing formats are Mermaid, CSV, Markdown, and HTML; JSON supports machine use. HTML is self-contained where promised; Mermaid requires a compatible renderer.
- No fixed lifetime quota is required, but collection is memory-bounded and storage usage/retention/quotas are configurable. Active indexes may be replaced on rescan; explicitly saved historical traces retain required metadata/source references. Temporary traces may be discarded unless saved.
- Deleting records, projects, or all ThreadTrace data is permanent after confirmation. No encryption-at-rest requirement exists, but use restrictive local permissions.
- Saved traces retain source location, hash, and necessary snippets/snapshots. Historical locations never change; diff relocation is advisory only. Notes, bookmarks, and investigations are separately portable.
- Sensitive export is a deliberate local action with warnings and restrictive-permission guidance. `.gitignore` does not remove an already tracked secret.
- Provide selected JSON CLI output and a documented experimental Python interface. No remote public server API is required.

## AI behaviour

- AI is optional. Local Ollama and OpenAI-compatible endpoints are supported, configured by base URL, model, and credentials. Core analysis never depends on AI.
- Read keys from environment variables or a restrictive local `.env`; never export/log them. YAML holds nonsecret provider/model settings.
- Local models receive selected configured context. Cloud models receive only exact user-approved sections after best-effort redaction; never send whole environments or raw credentials by default. **Every remote AI request requires fresh approval of its exact submission.**
- Save prompts/responses locally until manual deletion or configured retention. Allow custom prompts/templates, model settings, temperature, token limits, and supported parameters, rejecting unsupported options cleanly.
- Use machine-validated structured output for explanations and diagrams. Validate AI diagram syntax and referenced nodes/edges against the analysis model; visibly distinguish evidence, inference, and unverifiable claims.
- AI may explain and create diagrams but is read-only against targets. Adapter/patch proposals are review artifacts requiring user approval before execution.

## UI, browser, safety, and quality

- Retain `prompt_toolkit`. The TUI is keyboard-first, supports compact fallback below a tested minimum terminal size, Unicode with ASCII fallback, no-colour mode, and non-colour status cues. Mouse use is optional.
- Browser views are read-only in v1.0, loopback-only, and use a dynamic localhost port by default with optional configuration. Mermaid is a required export/output and browser-rendered diagram source. Required graph families are dependency/import, call, class/module, AST, data-flow, and evidence-supported execution-flow views, with pan, zoom, search, filtering, focus, expansion, source navigation, and export. Use progressive rendering rather than a hard graph-size cutoff.
- Normal execution is an unsandboxed child subprocess with the user's privileges. Optional sandbox/container support is recommended for untrusted targets but not mandatory cross-platform v1.0. Python network hooks can request allow/deny/edit, but only real OS/firewall isolation guarantees denial. Filesystem restrictions are likewise sandbox responsibilities.
- Confirm first execution of unfamiliar code, risky experiments, sensitive capture, and source edits, explaining the action and likely resources. Keep diagnostics local by default; no automatic telemetry/upload. Bug reports contain environment/version/errors/resource metrics, while target source/data requires explicit approval.
- Benchmark representative fixtures before setting numerical performance thresholds. Stream/paginate traces and bound UI buffers. The acceptance suite includes scripts; multi-module packages; argparse/Click/Typer; Flask/FastAPI/Django; sqlite3/SQLAlchemy; asyncio/threads/multiprocessing; exceptions/imports/patches; and malformed projects.
- Deterministic supported fixtures must pass automated tests. Heuristics have separate precision/recall measurement. Every feature documents Full/Partial/Unsupported status, coverage, fallbacks, limitations, and acceptance tests.
- Use semantic application versions and separately versioned schema/export formats. Preserve supported v1.0 data through documented migrations and backups.

## Implementation discretion

Unspecified implementation details are delegated to the coding agent, provided they preserve this specification's safety, evidence, privacy, compatibility, and capability-status requirements. This includes the YAML configuration schema and fields, internal defaults/budgets, UI details, performance thresholds derived from benchmarks, and internal architecture choices.

The agent must document material choices in the relevant specification or an implementation decision record, label unsupported capabilities honestly, and must not expand scope by silently adding remote execution, automatic cloud submissions, or unapproved source changes.
