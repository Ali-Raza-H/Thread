# Capability Audit

> [!summary]
> This audit records the current implementation baseline. It is not a promise
> that an unfinished capability will behave as if it were complete.

## Static Analysis

| Capability | Status | Current boundary |
| --- | --- | --- |
| Python files, AST symbols, imports, calls, and syntax failures | Partial | Ordinary and namespace-package `.py` files are supported. Explicit external files, validated zip members, notebook cells, and generated text share the same AST pipeline. Parser recovery remains limited. |
| Source discovery and provenance | Partial | Safe traversal skips excluded directories and never follows directory symlinks; file symlinks outside the project require an explicit path. Every source records logical module, origin kind, original/resolved path, hash, parser version, capability, category, and origin identity. Zip members enforce path and expansion limits; notebook cells keep stable identity; generated text uses a virtual origin. Per-source read/syntax failures preserve unaffected findings, skipped sources retain reasons, and scan summaries classify source, test, generated, notebook, archive, metadata, resource, native, and unclassified files. REPL/source-free and native-extension bodies remain unsupported. |
| Entry points and common metadata | Partial | Scripts, console scripts, Flask/Quart/FastAPI/Starlette/aiohttp routes, Django URLconfs, middleware, lifecycle hooks, tests, argparse/Click/Typer/optparse commands, command registries, Celery/RQ/Dramatiq/Huey tasks, APScheduler jobs, and pluggy hooks are covered only when a framework import and registration object are present. DB-API, SQLAlchemy, and Django ORM access is recorded as syntax evidence. Route controls, dynamic registration, and complex protocols remain incomplete. |
| Project metadata and staleness | Partial | Parses `pyproject.toml`, `requirements*.txt` (recursive/constraints/editable/direct URLs/markers/extras), `setup.py`/`setup.cfg` literal values, `Pipfile`, `Pipfile.lock`, `poetry.lock`, `uv.lock`, and a bounded line-based Conda subset without execution. Dependency groups, markers, extras, URLs/paths, source files, statuses, and limitations persist; malformed/unrecognised metadata is preserved by hash. Scan inputs hash discovery settings, interpreter identity, metadata files, and source units. Staleness reports source, metadata, discovery, and interpreter causes with affected capabilities. Environment resolution and generated-text revalidation from hashes remain unavailable. |
| Relationships, resources, paths, impact, data flow, slices, and control flow | Partial | Results retain source evidence. A call becomes a confirmed direct relationship only through lexical, module, class, explicit-import, re-export, inherited, or stored binding evidence; unrelated same-name definitions stay `possible` candidates. Impact labels upstream and downstream calls, resolved references, import dependants, inheritance users, configured entry points, and affected resources, with a 500-record truncation marker. Data flow links resolved argument/return edges and literal resource sinks. Slices combine scoped def-use records with resolved interprocedural edges while retaining attribute, subscript, mutation, alias, index, reflection, and indirect-call boundaries. CFGs cover branches, loop break/continue, return/raise, try/except/else/finally, with/async-with, match, yield, and conservative call-exception edges under node/edge budgets. All results remain syntax-level and do not prove runtime selection or observed execution. |
| Structural complexity, algorithms, resources, and advanced Python facts | Partial | Cyclomatic count is separate from deterministic time/space estimates. Straight-line work, loop nesting, sorting/iteration/reduction calls, comprehensions, resolved project calls, recursion, and unknown external calls carry explicit assumptions or `unknown`. Resource classes distinguish configuration, structured data, text, templates, media, serialization, compression, packages, databases, services, queues, environment, interpreter use, diagnostics, files, and subprocesses, including path suffixes and unresolved dynamic expressions. Advanced syntax covers decorators/targets, generators, async constructs, context managers, closures/free names, descriptors, properties, metaclasses, dynamic attributes, concurrency creation, native boundaries, and tested heuristic algorithm patterns. Sensitive-data taint analysis remains explicitly outside v1. |
| Python-aware bindings and references | Partial | Scopes, imports, definitions, assignments, parameters, constants, `global`/`nonlocal`, comprehensions, aliases, forwarding imports, re-exports, `__all__`, wildcard imports, overload stubs, inherited attributes/descriptors, conditional imports, and `TYPE_CHECKING` are persisted. References and calls carry binding paths or explicit `unresolved`, `unresolved_attribute`, `conditional`, or `type_checking` outcomes. Installed/stdlib source locations are recorded without importing target modules; third-party symbol bodies are not traversed by default. Dynamic imports, `eval`/`exec`, reflection, and monkey patching become separate boundary facts. |
| Third-party source following | Partial | Standard-library and installed source locations are discovered from interpreter search paths without importing them. Only explicit external files and directly reached source units are parsed; full transitive third-party symbol expansion and zip-imported environments remain unavailable. |

## Dynamic Analysis

| Capability | Status | Current boundary |
| --- | --- | --- |
| Explicit local CPython child-process tracing | Partial | Calls, lines, returns, exceptions, session breakpoints, tracepoints, watchpoints, threads, available asyncio task identity, wall-clock timestamps, monotonic elapsed time, and process CPU time are captured. Values are cycle-safe with per-run identity links and configurable depth/item/byte summaries; changes distinguish binding creation, rebinding, deletion, in-place mutation, and native/opaque state. Breakpoint conditions and watch expressions use a restricted read-only AST grammar, and locations bind to source hash plus file/line/symbol identity. Pause and step commands are thread-specific. Failed runs correlate the final traceback and innermost project frame before using trace state/call chains, while retaining bounded handled/propagated exception evidence. `SystemExit` and `KeyboardInterrupt` are represented where observable; timeouts and conflicting evidence remain unknown. Reports also retain source hashes, a bounded stderr tail, safe state, and observed resource events. |
| Process, thread, task, and wait correlation | Partial | Stable run/process/thread IDs link instrumented Python parent and child processes; process events record PID, PPID, executable, argv, lifecycle, instrumentation status, and parent process identity. Thread lifecycle and observable asyncio task creation/completion plus coroutine suspend/resume are captured. Wait adapters cover thread joins, queues, futures, threading conditions/semaphores, asyncio locks/events/semaphores/conditions/queues, and async waits. `trace-concurrency` reports bounded lanes, durations, long waits, and low-confidence overlapping-wait deadlock heuristics. Native locks, uninstrumented/non-Python children, ownership, wakeup causality, and races are not claimed. |
| Runtime resource adapters | Partial | Saved Trace, controlled Runtime, and Host/Listener share bounded adapters for supported `urllib`, `urllib3`, Requests, HTTPX, aiohttp, SQLite, SQLAlchemy, Django database cursors, filesystem operations, and JSON/pickle serialisation. Safe wrappers publish final completed/failed status only after return/raise; audit-only events remain attempted and correlation IDs relate both phases. Default persistence redacts URL credentials/query values, headers/cookies, database parameters, sensitive environment values, exceptions, bytes, and nested mappings with explicit truncation. Adapters do not consume response streams or database cursors. Native extensions, unverified drivers, packet/TLS visibility, nested savepoint semantics, and operations outside an originating project Python stack remain unavailable. |
| Host/Listener | Partial | Host preserves the target terminal, requires explicit `--yes-run`, and stops the target process group with a bounded emergency kill. The read-only listener follows running sessions only by default, takes over after two seconds of listener silence, renders transport/status errors, and reports dropped events, journal truncation, and pending lag. Events arrive in pages capped at 200 events and 256 KiB. Session directories require current-user ownership and a 12-character identifier, expire after 24 hours, and running hosts heartbeat every ten seconds. On Unix-socket platforms a mode-0600 socket carries events; Windows Host/Listener IPC is not implemented, and Host retains a bounded local journal. |
| Runtime instrumentation, event schema, and profiling | Partial | A versioned event schema covers call, line, return, yield/resume, exception, import, C call, audit, process/thread/task, resource, and profiling categories. The run reports sys.settrace, sys.monitoring availability, sys.setprofile, audit, adapters, and coverage.py capability; monitoring currently reports a frame-local settrace fallback. Recording defaults to project code with explicit reached-third-party expansion and separate presentation filters. Journals stream under event budgets with truncation markers. Function call counts, observed durations, hot paths, and supported child-process peak memory are reported with tracer-overhead limitations. Pause, timeout extension, graceful stop, and forced stop are available. |
| Native trace-derived coverage | Partial | Persisted line events produce source-checked line/function coverage and directly observed branch bodies. A compatible coverage.py SQLite database is read separately with line granularity and provenance; unobservable outcomes remain unsupported, and external coverage is never merged. |
| Attachment and multiprocessing inheritance | Unsupported | Discovery can identify current-user Python processes but does not attach to them; child-process instrumentation inheritance is not yet implemented. |

## Hybrid and Interfaces

| Capability | Status | Current boundary |
| --- | --- | --- |
| Full Hybrid experimentation | Full | Named experiments provide private source copies, reviewed source patches/diffs, JSON-safe function/class sessions, persistent named instances, typed/recorded/fixture/expression inputs, step evidence, repeatable line-local/global edits, descriptor-aware temporary patches, imported-alias replacement, substitutions, unavailable/mock modules, HTTP/SQLite/filesystem/network/process adapters, side-effect records, generated boundary/invalid cases, deterministic time/UUID/random controls, replay nondeterminism checks, and structural comparisons between fresh baseline/modified copies. Comparisons reject stale registered source and persist exact source revisions, configurations, interpreter details, and workspace roles. Runs and JSON exports are persisted. Workspace diffs report modified, created, deleted, renamed, binary, and unreadable files with hashes and bounded previews; patches are syntax-checked, written atomically, and recorded with before/after hashes. Project removal deletes or explicitly preserves verified experiment workspaces and keeps retryable records when cleanup fails. Callable inspection reports Partial for closure-cell mutation and native implementation replacement when Python does not expose them. Execution is not an OS sandbox and does not claim external-state rollback. |
| Launch profiles, investigations, and trace bookmarks | Partial | Named commands persist locally and execute their configured Python interpreter, nonsecret environment overrides/removals, and working directory; each trace records the resolved executable, interpreter version, and environment policy. Secret-named overrides are rejected. Small JSON investigation records, trace-event inspection, and event bookmarks persist; rich investigation composition and export remain unavailable. |
| Terminal explorer | Partial | Static exploration and controlled runtime dashboards are available; compact-mode, configurable keybindings, and several planned views remain work. |
| Loopback browser companion | Partial | `threadtrace browser PROJECT` is read-only and exposes stored overview, architecture, and capability data on `127.0.0.1` or `::1`. Its deliberately single-threaded server handles one request at a time. |
| Evidence and capability reporting | Partial | Public result rows carry a versioned evidence record with class, mechanism, source/run reference, limitations, and the original confidence label. Static confidence is mapped to `statically resolved`, `heuristically predicted`, or `unknown`; runtime values become `observed at runtime` only when an event occurred or completed. Schema v17 preserves per-scan legacy confidence counts, evidence versions, lexical scopes, definitions, references, exports, dynamic boundaries, metadata/dependency records, and scan-input hashes. Capability queries accept project, scan, interpreter, runtime trace, feature, and entity scope and expose documented limitations; `Full` requires a verified boundary. Dynamic code, indirect registration, and unobserved runtime state can still leave evidence `unknown`.
| Configuration and persistence | Partial | A versioned nonsecret YAML subset validates storage, discovery globs, interpreter defaults, TUI/browser settings, runtime budgets, exports, and local AI settings; duplicate/unknown/secret/invalid fields are rejected. Per-project preferences are stored separately and merged with global defaults. Storage usage and quota thresholds are reported, retention pruning is explicit, and `trace_saving: none` avoids persisting CLI traces. Deletion commands cover traces, reports, projects, and all local records with workspace reports. Migrations back up the previous database and restore it on failure; WAL, foreign keys, a five-second busy timeout, and restrictive permissions provide deterministic local coordination. Long-running retention/quota enforcement and platform-specific ACL parity remain partial. |
| Exports and CLI failures | Partial | Report commands support text, JSON, Markdown, CSV, and self-contained HTML; architecture adds Mermaid and DOT with escaped labels; `experiment diff` is text or JSON; interactive commands accept only text. Unsupported command/format pairs exit with code 2 instead of falling back to text, and expected configuration, database, and migration failures exit with code 2 without a traceback. JSON, CSV, and graph stdout stays machine-readable while warnings go to stderr. |

## Verified baseline

The automated suite covers deterministic static analysis, incremental scans,
safe source discovery (namespace packages, explicit external files, zip members,
notebook cells, generated text, and symlink rejection), Python-aware bindings
(shadowing, re-exports, wildcard imports, overloads, inherited attributes,
conditional/`TYPE_CHECKING` imports, references, usage, and boundaries), directional
impact, scoped def-use slices, resource-correlated data flow, complex CFG
constructs and truncation budgets, structural complexity/advanced facts and
expanded resource classes, incremental import reuse, metadata
parsing and cause-based staleness, runtime event schema/instrumentation planning,
profiling and coverage.py provenance, runtime sessions,
truthful resource outcomes and redaction, terminating/handled exception failure reports, Host/Listener behaviour, full Hybrid harness/adapters/replay/comparison,
configuration validation, real loopback browser endpoints and bounded failures,
and export rendering under CPython 3.11. Other Python
versions and interpreters retain the status documented above until tested.
