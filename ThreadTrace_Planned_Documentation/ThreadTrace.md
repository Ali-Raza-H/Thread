# ThreadTrace

> [!abstract] Working specification
> ThreadTrace is a Python reverse-engineering and runtime-analysis tool. [[v1.0 Product Decisions]] is the current product authority; the feature catalogue describes the intended capability surface and the alpha codebase remains subject to an implementation audit.

## Purpose

ThreadTrace helps a user understand an unfamiliar Python project in three complementary modes:

| Mode                 | Purpose                                                                            |
| -------------------- | ---------------------------------------------------------------------------------- |
| [[Static Analysis]]  | Understand project structure and possible behaviour without executing target code. |
| [[Dynamic Analysis]] | Observe execution under instrumentation.                                           |
| [[Hybrid Analysis]]  | Experiment with controlled changes, substitutions, and inputs.                     |

All modes use [[Shared Systems]], a common [[Data Model and Persistence|analysis model]], [[Safety and Performance|safety controls]], and the [[TUI Design|TUI]] as their primary controller.

## Documentation conventions

- **Static fact**: determined from source without execution.
- **Runtime observation**: directly recorded during an instrumented [[Run]].
- **Inference**: plausible relationship or estimate, labelled with confidence.
- **AI interpretation**: explanation generated by an AI provider; never presented as verified analysis.
- **Later implementation**: intentionally deferred capability, rather than a current guarantee.

See [[System Architecture#Evidence and confidence]] and [[Capability Model]] for the governing rules.
